# Миграция и обновление

Основная часть страницы — про v1.0 → v1.1, потому что именно тот релиз менял поведение. v1.1 → v1.2 был аддитивным: только новые API и четыре небольших смысловых изменения в разделе [Обновление с 1.1](#обновление-с-11).

v1.1 сохраняет четыре публичные концепции v1.0 (`Chroms.Game`, `Chroms.Scene`, `Chroms.Sprite`, `Chroms.Text`) и форму `this.add` / `this.physics`, поэтому большинство небольших игр работают без изменений. Ниже — различия в поведении, которые могут удивить.

## Код v1.0

```js
class PlayScene extends Chroms.Scene {
  constructor() {
    super('PlayScene');
  }

  create() {
    this.player = this.add.sprite(380, 280, 40, 40, '#89b4fa');
    this.target = this.add.sprite(200, 150, 25, 25, '#f9e2af');
    this.scoreText = this.add.text(20, 35, 'Score: 0', {
      font: 'bold 22px sans-serif',
      color: '#cdd6f4'
    });
  }

  update(dt) {
    this.player.setVelocity(320, 0);
    if (this.physics.overlap(this.player, this.target)) {
      this.scoreText.setText('Score: 10');
    }
  }
}

new Chroms.Game({
  width: 800,
  height: 600,
  backgroundColor: '#1e1e2e',
  scene: [PlayScene]
});
```

Это по-прежнему работает. Спрайты без тел принимаются `physics.overlap` как статичные AABB-прокси.

## Что изменилось

### Жизненный цикл и очистка

- `create()` вызывается после загрузки ассетов из `preload()`, а не до ручного `load.start`.
- Переключение/рестарт сцены **уничтожает** её объекты и тела, очищает `scene.tweens` и `scene.time`.
- Новый хук `shutdown()` вызывается перед уничтожением.
- `game.startScene` принимает `{ fade }`.
- Появились `scene.pause()`, `resume()`, `sleep()`, `wake()`.

Если объекты должны переживать смену сцены, храните состояние в `game.storage`, глобале или менеджерах уровня игры.

### Физика

- Тела интегрируются в мире с фиксированным шагом **после** `scene.update()`. В v1.0 спрайты двигались во время рендера.
- Появились гравитация, ускорение, drag, максимальная скорость, отскок, сенсоры, границы мира и коллизии с тайлмапом.
- `physics.overlap(a, b)` остаётся булевым запросом и принимает объекты без тел, но для расталкивания нужны настоящие тела.
- Постоянные коллизии — `physics.addCollider` / `physics.collide`; регистрируйте один раз.
- `sprite.setGravityY()` создаёт тело по требованию. Внутренний `updatePhysics()` удалён.
- Поворот, origin и масштаб не меняют тело; только AABB.

### Отрисовка и объекты

- Переопределённый `draw(ctx)` получает локальные координаты с `(0, 0)` в левом верхнем углу бокса объекта (с учётом origin), а не абсолютные мировые.
- Текст теперь по умолчанию с `textBaseline = 'top'`. В v1.0 использовался canvas-дефолт (`alphabetic`), поэтому текст на том же `y` смещается примерно на высоту строки. Поправьте `y` или задайте `style.baseline: 'alphabetic'`.
- `Sprite.x/y` по-прежнему левый верхний угол; `setOrigin()` новый, значение по умолчанию всё ещё `0, 0`.
- Появились `depth`, `blendMode`, `scrollFactor`, анимации, фигуры, тайлмапы, частицы и UI-объекты.
- Дети сцены сортируются по depth; v1.0 рисовал в порядке добавления.

### Менеджер сцен

- В v1.0 был патч конструктора, создававший сцены без аргументов. В v1.1 вызывается `new SceneClass()`; поддерживаются `super('Key')` и `super({ key })`.
- Сцены можно регистрировать, не запуская все сразу; `startScene` явный.
- `scene.camera` — теперь объект `Camera`, а не `{ x, y, zoom }`. Установка `camera.x/y/zoom` по-прежнему меняет скролл/зум, но для follow, границ, тряски и затуханий используйте методы.

### Загрузчик

- `load.start(onComplete)` работает; добавлен `load.start(onProgress, onComplete)`.
- Очередь очищается после загрузки, ошибки собираются в `loader.errors`.
- Добавлены `spritesheet`, `atlas`, `json`, `text`.
- JSON/text используют `fetch`, нужен HTTP.

### Аудио

- `sound.play(key, volume)` (число вторым аргументом) всё ещё принимается.
- Предпочтительно: `sound.play(key, { volume, rate, loop, channel })`.
- Добавлены `musicPlay`, `stopMusic`, управление громкостью и `beep`.
- `sound.play` возвращает handle или `null`.

### Игровой цикл

- `dt` ограничивается и масштабируется.
- Физика использует собственный аккумулятор; `scene.fixedUpdate(step)` выполняется детерминированными шагами до `update`.
- `game.pause()` останавливает симуляцию, но продолжает рендер.
- Появились `game.timeScale`, `game.time`, `game.tweens`, плагины, debug-оверлей, режимы масштаба и `screenshot()`.

## Обновление с 1.1

1.2 добавил несколько активных сцен, слои коллизий, UI-виджеты, полигоны, тинт спрайтов, события указателя на объектах, комбинации клавиш, цветовые твины, `repeatDelay`, снимки хранилища, паузу музыки и объектные слои тайлмапов. Старый код продолжает работать. Проверьте эти допущения:

- **`startScene` не изменился** — он по-прежнему останавливает все остальные активные сцены. Оверлеи, HUD и меню паузы запускаются через `launchScene` / `scene.launch`; стек отдаёт `game.getActiveScenes()`.
- **Физика знает о сценах** — тела приостановленных и спящих сцен заморожены, остальные сцены продолжают симуляцию. Код, который ставил сцену на паузу и ждал движения её тел, должен её возобновить.
- **`body.scene` читается из объекта** — `object.addTo(otherScene)` переносит тело в новую сцену, и сценовый фильтр следует за переносом.
- **Анимации снимаются с учёта при остановке и завершении** — `anims.sprites` больше не копит все спрайты, которые когда-либо играли. Проверяйте `sprite._anim.playing` (или `isPlaying()`), а не членство в реестре.
- **`camera.panTo()` важнее `follow()`** — слежение приостанавливается на время панорамы и возвращается после неё.

1.2.1 исправил пять багов без изменения API: сцена после сна снова рендерится после перезапуска, `panTo` не перебивается follow, флаг паузы музыки не переживает `stopMusic()`, перенесённые тела остаются в правильной сцене, а остановленные и завершённые анимации покидают реестр.

## Проверка версии

```js
if (Chroms.version.startsWith('1.2')) {
  // используем API 1.2
}
```

`Chroms.VERSION` тоже доступен.

## Исправленные странности 1.0

- Загрузчик больше не оставляет завершённую очередь, поэтому `start()` не запускает старые элементы.
- Handle звуков отслеживаются и останавливаются.
- Ошибки изображений не блокируют очередь; остаётся цветной fallback.
- Переключение сцены не оставляет старые объекты и таймеры.
- Ресайз холста сохраняет пропорции и корректно пересчитывает координаты указателя.
